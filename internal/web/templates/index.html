What is the μTandae Protocol?

Protocol v1 · application/vnd.mutandae.v1+json

What it is

A small, versioned, provider-neutral lifecycle and rotation protocol for machine identities — JSON over HTTP, media type application/vnd.mutandae.v1+json.

One canonical state machine (registered → active → renewing → retired), one event vocabulary (identity.discovered, identity.registered, rotation.*, credential.delivered/credential.used/credential.revoked, identity.retired), one audit shape — spoken identically by the Azure/Entra ID, AWS IAM, and GCP IAM adapters.

Why it exists

Machine identities are fragmented across provider-specific APIs; ownership, expiry, and renewal health are invisible; credential renewal is manual, inconsistent, and operationally risky.

Without a shared contract, every governance tool reinvents provider plumbing and audits nothing the same way twice.

The value it brings

Portability across clouds — the same lifecycle verbs over Azure, AWS, and GCP. Evidence for every change: each rotation, use, and revocation is an audited event with actor, outcome, and vault reference — never secret material.

Renewal health at a glance, and an honest open-core boundary: the protocol and frontend are public; production renewal engines stay private.
