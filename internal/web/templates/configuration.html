Connect what
you own.

Create real, zero-permission identities in the Azure, AWS, and GCP tenants this demo governs, or open a short-lived session against an Azure / Entra tenant you control. Real-tenant credentials never enter Redis, snapshots, events, logs, or HTML.

Security warning. Only use a temporary client secret for a tenant you own. Mutandae holds it in process memory for at most ten minutes and clears it when the session ends. After trying the demo, invalidate this client secret in Entra ID and remove its consent if you no longer need it.

Create a zero-permission identity in a real tenant

Pick the identity type and press New identity: the identity is created for real in that cloud's tenant with no permissions (no AWS policy, no GCP role, no Azure API permission or admin consent) and the secret is mirrored into the cluster vault. You can retrieve it again any time; every use and renewal is logged. The demo auto-reclaims the oldest identity at its quota and throttles requests per client.
